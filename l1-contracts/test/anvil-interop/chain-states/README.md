# Chain-state fixtures

Two kinds of directories live here, with OPPOSITE maintenance rules. Both names come from
`config/anvil-config.json`.

- **`upgradeSourceStateVersion` — FROZEN previous-release fixture.** The ecosystem the current
  release's edge departs from, copied byte for byte from the previous release's branch. It is the
  input of `run-upgrade-test.ts` and of the Foundry upgrade tests (`PreviousReleaseFixture`, which
  loads its L1 state) and MUST NEVER be regenerated: contract changes on this branch must not touch it,
  exactly like the real chains it stands in for. Its `AllContractsHashes.json` is that release's:
  `ReleaseDeclaredChangesTest` requires every ecosystem
  implementation or release member the release's prepare checks for reuse, if its creation code has
  changed since then (a constructor-only change included), to be declared.

- **`stateVersion` — current-genesis states.** Generated from THIS branch's sources by
  `setup-and-dump-state.ts`, consumed by the interop tests and `run-recurring-upgrade-test.ts`,
  regenerated by the 'Regenerate Anvil Interop Chain States' workflow whenever contracts change,
  and validated by the `state-generation-check` CI job.

When the next release starts, `yarn new-release` freezes the then-current `stateVersion` as the new
`upgradeSourceStateVersion`, records the genesis root its chains were created from as
`upgradeSourceGenesisRoot`, freezes the release's `AllContractsHashes.json` next to it, deletes the
outgoing source, and moves `stateVersion` on.
