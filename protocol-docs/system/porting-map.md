# `zksync-era` system architecture porting map

The first commit of this documentation series ports the complete architecture source from
`zksync-era`'s `kl/interop-docs` branch without edits: `docs/src/specs/contracts/**`,
`docs/src/specs/design/**`, and the supporting introduction, overview, blocks/batches, and L1-contract
pages. This map records where every subject lives after updating the documentation to the current
`era-contracts` release.

| Ported source                                                                                     | Current home and status                                                                                                                                                                                                                                                                                                                    |
| ------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `specs/introduction.md`, `overview.md`, `blocks_batches.md`, `l1_smart_contracts.md`              | [System architecture](./README.md) is the current entry point. Settlement details remain under [settlement contracts](./contracts/settlement_contracts/zkchain_basics.md) and [EraVM](./contracts/zkevm/overview.md).                                                                                                                      |
| `specs/contracts/README.md`, `overview.md`, `glossary.md`                                         | [System architecture](./README.md) and the domain-specific pages it links replace the old WIP index and obsolete interop terminology.                                                                                                                                                                                                      |
| `specs/contracts/chain_management/**`                                                             | Retained under [chain management](./contracts/chain_management/overview.md), with current genesis, registration, migration status, and ZKsync OS behavior centralized in [chain lifecycle](../chain-lifecycle.md).                                                                                                                         |
| `specs/contracts/bridging/**`                                                                     | Replaced by [bridging](../bridging.md) and its concise [architecture entry](./contracts/bridging/overview.md). The old direct-withdrawal diagrams and L1/Gateway asset trackers no longer describe this branch; the surviving L2 tracker is covered in the current bridge document.                                                        |
| `specs/contracts/interop/**`                                                                      | Replaced by [interop](../interop.md), [interop architecture](../interop/architecture.md), [message root](../message-root.md), [atomicity](../atomicity/README.md), and the [interop-specific porting map](../interop/porting-map.md). The trigger, aliased-account, public-message-proof, and automatic-execution designs are not current. |
| `specs/contracts/settlement_contracts/priority_queue/**`                                          | Retained under [priority operations](./contracts/settlement_contracts/priority_queue/README.md); current message-root and atomic proof structures are documented separately because they are shared across settlement and interop.                                                                                                         |
| `specs/contracts/settlement_contracts/data_availability/**`                                       | Retained under [data availability](./contracts/settlement_contracts/data_availability/README.md), covering pubdata, compression, reconstruction, rollup, validium, custom DA, and the standard pubdata format.                                                                                                                             |
| `specs/contracts/gateway/**`                                                                      | Retained as [dormant settlement-layer architecture](./contracts/gateway/README.md). The contracts remain, but production migration is disabled; [chain lifecycle](../chain-lifecycle.md#settlement-layer-migration-chainassethandler) is normative for current behavior.                                                                   |
| `specs/contracts/consensus/**`                                                                    | Retained under [consensus](./contracts/consensus/README.md).                                                                                                                                                                                                                                                                               |
| `specs/contracts/zkevm/**`                                                                        | Retained under [EraVM / zkEVM](./contracts/zkevm/overview.md). These pages describe the EraVM execution environment and do not claim that ZKsync OS uses the same bootloader or system-contract internals.                                                                                                                                 |
| `specs/design/atomicity_using_l1_finality.md`, `atomicity_using_da_and_onchain_simulation.md`     | Replaced by the implemented [atomicity protocol](../atomicity/README.md).                                                                                                                                                                                                                                                                  |
| `specs/design/l1-interop.md`, `private-interop.md`, `private-l1-interop.md`, `shadow-accounts.md` | These proposals are not implemented. Current public interop, sender identity, L2 -> L1 restrictions, and privacy properties are documented in [interop architecture](../interop/architecture.md).                                                                                                                                          |
| `specs/design/bank-governance.md`, `streamlining_upgrades.md`                                     | These design proposals are not the deployed governance and upgrade protocol. Current CTM upgrades are documented under [chain management](./contracts/chain_management/upgrade_process.md).                                                                                                                                                |

The old pages that described removed or speculative protocols are intentionally absent from the final
tree. They remain visible in the raw-port commit, making the modernization diff explicit without
leaving two conflicting protocol specifications in the repository.
